# PS Gift Card Stock Monitor 🎮

בודק ברציפות את כל כרטיסי המתנה של PlayStation Store הודו באמאזון הודו (12 מוצרים, ראו `products.txt`), ושולח הודעת טלגרם ברגע שאחד מהם חוזר למלאי.

- 🟢 הודעה מיידית עם כפתור **🛒 Add to cart**, המחיר והמוכר (ותזכורת כל 5 דקות כל עוד במלאי)
- 🔕 כפתור **Mute until next restock** בהודעה — מפסיק תזכורות על המוצר עד שהוא יוצא מהמלאי וחוזר (למשל כשהדף מראה מלאי אבל בתשלום כבר נגמר)
- 🔴 הודעה אם המוצר אוזל שוב
- 🛡️ אם אמאזון חוסמת (captcha / 503) — עוצר לכמה שניות ואז ממשיך לבד
- 💻 ב-Windows מונע מהמחשב להיכנס לשינה כל עוד הסקריפט רץ

## הרצה על המחשב (Windows)

1. התקן [Python](https://www.python.org/downloads/) (3.10 ומעלה) — בהתקנה סמן ✅ **Add python.exe to PATH**.
2. הורד את הקוד: **Code → Download ZIP** וחלץ לתיקייה (או `git clone`).
3. בתיקייה, העתק את `.env.example` לקובץ בשם `.env` ומלא את `TELEGRAM_BOT_TOKEN` ו-`TELEGRAM_CHAT_ID`.
   (ה-Secrets ב-GitHub משמשים רק את GitHub Actions — המחשב קורא מ-`.env`.)
4. לחיצה כפולה על **`start.bat`**. הוא מתקין את מה שצריך, מריץ, ומפעיל מחדש אם משהו קורס.

תוך שנייה תגיע לטלגרם הודעת "👀 Stock monitor started" עם רשימת המוצרים.

בחלון יופיע לוג: שורה כשמצב של מוצר משתנה, ושורת `Round` אחרי כל סבב על כל המוצרים (כמה זמן לקח, מה במלאי, וכמה חסימות היו).

## קצב בדיקה

`CHECK_INTERVAL` = שניות בין תחילת בקשה לתחילת הבקשה הבאה (ברירת מחדל `3`). זה הקצב **המהיר ביותר**: אחרי חסימה הסקריפט מאט אוטומטית (×2, עד `MAX_CHECK_INTERVAL`) וזוכר את הקצב שנחסם בו (גם אחרי הפעלה מחדש, בקובץ `pace_state.json`), ואחרי כל 5 דקות בלי חסימות מאיץ שוב — אבל לא מתחת לקצב שנחסם בו. הקצב הנוכחי מופיע בשורת ה-`Round` כ-`pace`. אם אמאזון עונה לאט יותר מזה, הבקשה הבאה יוצאת מיד כשהקודמת חוזרת. הבקשות עוברות בסבב על כל המוצרים, כך שכל מוצר נבדק כל `CHECK_INTERVAL × מספר המוצרים` — עם 12 מוצרים ושנייה אחת, כל מוצר נבדק כל ~12 שניות.

- רואים הרבה `blocks` בשורות ה-`Round`? העלו ל-`2`–`3`. בדיקות שנחסמות לא בודקות כלום.
- אם אמאזון חוסמת ברצף יותר מ-10 דקות תגיע הודעת ⚠️ לטלגרם (והודעת ✅ כשזה משתחרר). חסימה ארוכה = כרגע לא בודקים כלום: העלו את `CHECK_INTERVAL`, או אתחלו את הראוטר כדי לקבל IP חדש.
- הבקשות נשלחות דרך `curl_cffi`, שנראה לאמאזון כמו דפדפן Chrome אמיתי — זה מפחית חסימות משמעותית.
- רוצים מהר יותר למוצר מסוים? הוסיפו `#` בתחילת השורה של מוצרים שלא מעניינים אתכם ב-`products.txt` — פחות מוצרים = כל אחד נבדק יותר מהר.

## בדיקה ידנית (debug)

הדף האחרון שהסקריפט ראה לכל מוצר נשמר ב-`debug/<ASIN>.html`. אם הסקריפט אומר "out_of_stock" ובאפליקציה רואים מלאי — פתחו את הקובץ בדפדפן ותראו מה אמאזון הראתה לסקריפט. בתחילת הריצה גם מופיעה שורת `Amazon delivery location` שמראה לאיזה מיקום אמאזון מחשבת זמינות.

## עריכת רשימת המוצרים

`products.txt` — שורה לכל מוצר: `ASIN | שם`. ה-ASIN הוא הקוד אחרי `/dp/` בכתובת המוצר באמאזון.

## הגדרות (בקובץ `.env`)

| משתנה | ברירת מחדל | תיאור |
|---|---|---|
| `CHECK_INTERVAL` | `3` | שניות בין בקשות |
| `MAX_CHECK_INTERVAL` | `8` | הקצב הכי איטי שהסקריפט יירד אליו אחרי חסימות |
| `REMIND_EVERY` | `300` | כל כמה שניות לשלוח תזכורת כשמוצר במלאי |
| `IGNORE_SELLERS` | (ריק) | מוכרים להתעלם מהם, מופרדים בפסיק (למשל `Express Games` — הדף מראה מלאי אבל בתשלום הכמות 0) |
| `BLOCK_ALERT_AFTER` | `600` | אחרי כמה שניות של חסימה רצופה לשלוח התראה |
| `DELIVERY_PINCODE` | `400001` | פינקוד הודי למשלוח (מומבאי). אמאזון מציגה מלאי לפי מיקום — בלי זה מוצרים זמינים יכולים להיראות לא זמינים |
| `PRODUCTS_FILE` | `products.txt` | קובץ רשימת המוצרים |
| `MAX_RUNTIME` | `0` | זמן ריצה מקסימלי בשניות (`0` = לנצח) |

## הרצה ב-Linux / Mac

```bash
pip install -r requirements.txt
cp .env.example .env   # ומלא את הערכים
python monitor.py
```

## GitHub Actions (אופציונלי, ידני בלבד)

ה-workflow רץ רק בהפעלה ידנית (Actions → Stock monitor → Run workflow). **לא להריץ במקביל למחשב** — שני עותקים מכפילים את העומס על אמאזון (וה-IP של GitHub נחסם מהר) ושוברים את כפתורי הטלגרם.
